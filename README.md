# TraceLit

TraceLit is a visual debugger for LeetCode-style problems.

Instead of guessing what your code is doing, TraceLit lets you **see execution step by step** — including variable changes, call stack transitions, and data structure updates — so you can debug faster and understand your code more deeply.

## Why TraceLit?

Debugging algorithm problems is frustrating because:

- print debugging is noisy and slow
- dry-running in your head is error-prone
- recursion and pointer mutations are hard to track
- wrong answers often come from one subtle step that is easy to miss

TraceLit makes execution visible.

## Features

- Step-by-step code execution
- Call stack visualization
- Variable change tracking
- Data structure state inspection
- AI-assisted debugging for wrong answers and runtime errors
- Fast workflow for LeetCode-style inputs

## Best for

TraceLit is especially useful for:

- recursion
- binary trees
- linked lists
- DFS / backtracking
- pointer manipulation
- dynamic programming state tracing
- debugging wrong answers and runtime errors

## How it works

1. Paste your solution
2. Paste a test case
3. Run the code
4. Step through execution
5. Inspect the trace and find the bug

## Why I built it

I got tired of dry-running code by hand.

For recursion, trees, backtracking, and pointer-heavy problems, the hardest part often is not writing the code — it is understanding what actually happened during execution.

So I built TraceLit to make runtime behavior visible.
